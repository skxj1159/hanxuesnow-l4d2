## 1. 架构与数据流

```
渲染线程 (DX9 EndScene)
  └─ Menu::DrawCallBack
       ├─ LiveEsp::LiveFrameBegin   → 发布实体快照 g_entities（唯一权威写入方）
       └─ Aimbot::RefreshBonesForFrame
            └─ BoneSysRefreshEntities(entIndices, count)   ← 【取骨唯一入口】
                 · 门控：切图冷却 2s(硬上限) / 窗口失焦 / curtime 倒退
                 · 预算：每帧 24 次 SetupBones 直调，**轮转起点**（s_rrCursor）
                 · 结果写入 g_boneStore[ent].m（每实体一份，带 stampMs）

游戏线程 (CreateMove, 66Hz)
  └─ Aimbot::CreateMove
       ├─ UpdateTickClock(tick_count)  → g_cmdDt、g_curtimeEst（单调累加）
       ├─ GetBestTarget(eye, fovEff, tgt)   ← 选靶（评分/可见性/软锁/迟滞）
       ├─ 反应延迟判定（仅索引切换才重置）
       ├─ SolveTargetAngle()  → 重新取点 + EMA → 目标角
       └─ LegitApply() / RunSilentAim()     ← 写视角（含距离自适应平滑）
```

**线程安全约定**
- `g_entities` 只在渲染线程写；游戏线程**持锁复制**到 `thread_local snapCopy` 再遍历（批16 起，跨线程引用会堆损坏）。
- `g_boneStore` / `g_appearCount` / `g_negCache` / `g_hdrCache` 全部 SRWLOCK 保护。
- `g_cache`（HitboxSystem 帧内缓存）同样加锁。

## 2. 选靶流水线（GetBestTarget）

顺序：**白名单 → 存活/幽灵/队伍 → 最小锁定 → FOV 锥 → 评分 → 碰撞盒/Z 门 → 漂移门 → 多点可见性 → 最低分胜出**

任何一环失败即弃权该候选，**无任何兜底坐标**（批112 起彻底删除 `Origin+64` 与"胸骨兜底"）。

### 2.1 候选来源
- 快照 = 渲染线程发布的玩家实体（CTerrorPlayer / 特感 7 类 / 敌对幸存者）。
- **普通感染者（`kInfected`）与小僵尸不进入候选**（用户明确要求）。
- 休眠实体（`IsDormant`，离开 PVS）跳过：位置是冻结的旧数据。

### 2.2 评分
```cpp
score = ang + distWeight * (distM / 30.0f);   // 角度 + 距离权重
```
- `ang`：准星到**真实头点**的夹角（度）。
- `distM`：eye → 目标 origin 的三维距离（米，×0.0254）。
- **迟滞偏袒按可见性分级（批145）**：

| 上一目标状态 | 偏袒 | 用意 |
|---|---|---|
| 真的可见 | `score -= 15.0f` | 极强粘性，别乱换靶 |
| 只是软锁撑着（被小僵尸挡） | `score -= 3.0f` | 弱粘性，让掩体外的新目标能抢过来 |

> 批134 之前是**无条件 -15**，导致"被挡住的旧目标"霸占锁定位 —— 表现为「僵尸明明在掩体外却不瞄准」。批145 修正。

## 3. 三大状态机（本次评估重点）

### 3.1 软锁 / 最小锁定（`s_minLockUntil`）

| 项 | 值 |
|---|---|
| 计时器 | `DWORD s_minLockUntil`（文件作用域） |
| 时长 | **300ms**（换靶时 `GetTickCount() + 300`） |
| 效果 | 窗口内除上一目标外，其余候选直接 `continue` |
| 提前解除 | ① 本轮无任何候选（目标死/出 FOV）② 胜出目标只是软锁撑着（`winnerGrace`） |

### 3.2 反应延迟（`s_reactionUntil`）

```cpp
else if (tgt.index != s_lastTarget)   // 仅索引真正切换才重置
{
    s_reactionUntil = nowMs + (lo + rand() % span);   // 140~240ms
}
if (nowMs < s_reactionUntil) return;                   // 延迟中全透传
```
- **只比索引、不比实体指针** → 引擎复用槽位时会被误判成"同一目标"（已知边界）。
- `humanize.enabled == false` 时 `s_reactionUntil = 0`、`s_lastTarget = -1`（总闸真实生效）。
- 起手前 3 tick 强制 `jitOff = 0`（`s_lockTicks < 3`），避免随机偏移把起手方向带偏。

### 3.3 宽限期 + 防穿墙（Grace Period）

| 项 | 值 |
|---|---|
| 时间窗 | **180ms**（`nowV - s_lastVisMs[vi] <= 180`） |
| 前置条件 | 必须是上一帧的目标（`c.index == s_prevTargetForHysteresis`）且瞄准点位移 **< 96 单位** |
| 每帧 TraceRay | ✅ 是：`TraceBlockedByWorld(eyePos, s_lastVisPos[vi], localPlayer)` |
| 判定 | `tr.m_pEnt == nullptr` ⇒ 命中**世界几何（墙）** ⇒ `grace = !wall` ⇒ **立即丢弃该候选** |
| 实体遮挡 | 命中别的实体（小僵尸/栏杆）⇒ 保留软锁，直到 180ms 用尽 |

> 批136 之前还有"连续不可见 >3 帧就释放"的硬上限。**它已被删除** —— 因为 `s_visMiss` 不归零，目标被挡 4 帧后永久失去宽限资格 → 立刻丢靶 → 换远处目标 → 重走反应延迟 → 一顿一顿（实测软锁=0 次）。

**缓存变量命名**：代码里是 `s_lastVisMs[vi]` / `s_lastVisPos[vi]`（按实体索引 `& 255` 分桶），即"最后一次真正可见的时刻 / 瞄准点"。

## 4. 平滑（LegitApply）

```cpp
float S = clamp(g_Config.humanize.smoothFactor, 0.05f, 0.95f);   // 菜单基准
if (distUnits > 0) {                                            // 距离自适应
    k = (dist<=300) ? 0.85 : (dist>=800) ? 1.10 : 线性;
    S = clamp(S * k, 0.20f, 0.95f);
}
frac = 1 - powf(S, 66*dt);      // 每 tick 走剩余距离的 (1-S)
```
- 语义：**S 越大越慢**（批5 实测纠正过）。
- 距离单位是 **Source unit**：300u≈7.6m、800u≈20m。
- **铁律：距离系数只影响平滑层，绝不进入选靶评分。**
- 单 tick 位移硬上限 **4.5°**（与静默曲线共用反检测边界；Lilac SNAP2 阈值 5°）。
- 死区 `deadzone` 带退出滞后（×2 滞回），防临界点反复开关。

调参对照（菜单 smoothFactor=0.82 时）：

| 距离 | k | S | 每 tick 位移 |
|---|---|---|---|
| <300u | 0.85 | 0.70 | ≈30% |
| 500u | 0.975 | 0.80 | ≈20% |
| >800u | 1.10 | 0.90 | ≈10% |

## 6. 骨骼链路（BoneSystem）

| 环节 | 实现 |

| 取骨唯一入口 | `BoneSysRefreshEntities`（渲染线程） |

## 7. hitbox 调查结论（未通，且是死路）

**链路目标**：`m_nModelIndex → IVModelInfoClient::GetModel(int) → model_t* → GetStudiomodel → studiohdr_t* → hitbox set`

尝试记录：

| 方案 | 结果 |
|---|---|
| networkable 槽 8（`mov eax,[ecx+5C]; ret`） | 从未返回有效指针（`slot8 dump` 0 条） |
| modelinfo vtable 扫"读栈参数"槽 | 候选 0 → 2（slot 33/35，含 `8B 55 08` = mov edx,[ebp+8]）→ 调用返回 0/AV（实为**指针参数**函数） |
| 实体 vtable 扫签名 `8B 41 5C`（放宽到 3 字节） | 0 命中 |
| 实体 vtable 扫 `8B 41 5C` 且全槽扫 | 0 命中 |
| **对着磁盘 client.dll 离线反汇编** | **行不通**：32 个槽的 8 字节特征在磁盘模块里一个都搜不到 → 磁盘与运行时代码不一致 |
| **把内存里 64 字节/槽落盘后离线 capstone** | 反汇编结果是 `call 0xff568bf6` 这种**不可能的指令** → **该构建 .text 在内存中是混淆/加密的** |

**安全阀（批143，已生效）**
```cpp
constexpr bool kAllowModelInfoCalls = false;   // 只读探测保留，vcall 关闭
```
停用后**闪退消失**，反证：此前我们一直在调用被混淆的代码 → 写坏栈 → `0xc0000409`。

**结论**：hitbox 降级为待办。前提条件是拿到**解密后**的代码（调试器附加 / 正常调用一次后再 dump）。当前瞄准点位用骨名直取的头骨中心，精度已获用户认可。

## 8. 闪退调查结论

- 事件日志实锤 5 次：`ucrtbase.dll / 0xc0000409`（BEX，`__fastfail`，栈或 GS 被破坏）+ 1 次 `tier0.dll / 0x40000015`（引擎 Host_Error）。
- `0xc0000409` **绕过 UnhandledExceptionFilter** → 自建崩溃记录器抓不到（"静默消失"的由来）。
- WER LocalDumps 已配置（HKCU，DumpFolder=`C:\Temp\wb_verify\crashdumps`，DumpType=2，DumpCount=5），但因游戏自身处理/时机，**至今未产出 dump**。
- **根因定位：批143 安全阀后不再闪退** → 元凶是我们自己调用的未验证（且被混淆的）引擎槽位。
- 铁律更新：**「只读」不等于「便宜」** —— 跨引擎内存扫描每次非法地址读都是一次 SEH 恢复；扫描必须限速（批138：命中缓存 + 全扫描 3s 一次 + 全局 2s 节流）。
